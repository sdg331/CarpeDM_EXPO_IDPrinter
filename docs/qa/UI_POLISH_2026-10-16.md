# 새 3D 아이콘 적용 후 전체 UI 점검

## 결과와 수정 범위

새 카메라·경고·MirrorTing 제품 아이콘을 적용한 32개 기본 화면을 확인했다. 주요 로딩·오류·기록 없음·출력 결과 불확실 상태 22개, 웹 반응형 27개, 추가된 추천 근거 상세 표시 5개를 더해 총 86개 화면/상태/너비 조합을 재검사했다. 수정 후 검사한 범위에서 이미지 누락, 가로 넘침, 화면 밖으로 잘린 주요 버튼은 없었다.

| 확인한 문제 | 적용한 수정 |
| --- | --- |
| 사진 전용 인화 확인 카드의 두꺼운 검정 선과 각진 그림자가 공통 UI와 달랐음 | 바깥 카드에 둥근 모서리와 얇은 공통 선 적용, 그림자 제거. 흑백 사진과 QR 영역 유지 |
| 모바일 분석 안내와 기록 없음 제목이 문장 끝 한 글자를 다음 줄로 보냈음 | 웹 본문에 단어 단위 줄바꿈 적용. 긴 이름/문자열은 필요한 경우 나눔 |
| 모바일 결과 카드의 발급 정보가 좁은 오른쪽 칸에 묶였음 | 발급 정보를 카드 전체 폭의 하단 행으로 옮김 |
| 모바일 다음 체험 카드에서 제품 그림이 왼쪽에 치우쳤음 | 176px MirrorTing 그림을 카드 가운데 정렬 |
| 기록 조회 실패에도 기록 없음 카드가 표시되었음 | 오류 전용 제목·안내·복구 버튼 표시. 정상적인 기록 없음과 구분 |
| 미리보기의 기록 조회·사원증 준비 오류가 모두 AI 분석 실패로 표시되었음 | 해당 작업에 맞는 기존 오류 코드 사용 |
| 점검 중 별도로 추가된 추천 근거 패널이 키오스크 하단 행동을 밀어냈음 | 근거가 있을 때만 가로 프로필을 사용하고 근거 영역을 내부 스크롤. 표를 펼쳐도 행동 유지 |

이번 UI 작업은 현재 화면 ID, 버튼의 실제 흐름, 방문자 상태, 새 3D 이미지 파일, 백엔드 API와 감열 출력 양식을 변경하지 않았다. 작업 도중 추가된 별도의 얼굴 분석/추천 근거 변경은 보존했으며, 그 변경과 겹치는 결과 화면의 배치만 함께 확인했다.

## 화면 확인

| 구분 | 범위 | 조합 수 |
| --- | --- | ---: |
| 기본 키오스크 | 입사·퇴근·기념사진 전용·서비스 점검, 고정 800×1280 캔버스 | 23 |
| 기본 웹 | 홈·촬영·분석·결과·사원증 준비·사원증·다음 체험·퇴근·기록 없음 | 9 |
| 키오스크 예외 | 분석 오류, NFC 로딩/오류/결과 불확실, 배지 오류/결과 불확실, 퇴근 카드 로딩/오류/결과 불확실, 기록 조회 로딩/오류/기록 없음, 리포트 출력 오류/결과 불확실, 사진 전용 카드 로딩/오류/결과 불확실, 사진 인화 오류/결과 불확실 | 19 |
| 웹 예외 | 분석 오류, 사원증 준비 로딩/오류 | 3 |
| 추가 웹 너비 | 기본 웹 9개 × 추가 3개 너비 | 27 |
| 추가 추천 근거 | 키오스크·웹 4개 너비에서 실제 샘플 결과의 상세 표 펼치기 | 5 |
| 합계 | 중복 조합 제외 | 86 |

웹의 실제 측정 뷰포트는 389×843, 358×676, 769×1024, 1280×900 CSS px이다. 키오스크 미리보기에는 별도 설정 도구가 있으며 캔버스 자체는 800×1280을 유지한다. 클릭 시연에서는 800×1280 뷰포트에서 `scale(1)`을 확인했다. 앱의 확대 비율과 최소 창 너비 때문에 320px 요청은 실제 358px로 표시되어 320px 검증으로 세지 않았다.

각 조합에서 렌더링한 화면의 크기·가로 넘침·주요 버튼 위치·표시 이미지의 로딩을 검사하고 화면 이미지를 저장했다. 기본/예외 화면을 나란히 비교했고 수정한 사진 카드·웹 프로필·제품 안내·조회 오류를 다시 확인했다. 디지털 사원증은 비동기 생성 후 실제 배지 이미지가 나타나는 것도 확인했다.

추가 추천 근거는 처음에 합성 수치임을 명시한 레이아웃 전용 HTML로 버튼 밀림을 재현했다. 이후 이 작업에서 시작한 기존 8002 서버를 같은 장치 비활성화·화면 출력·별도 임시 DB 설정으로 재시작했다. 최신 `/api/match/landmarks`가 샘플 캐릭터 사진에 대해 응답하여 실제 측정 근거가 표시되는 결과를 다시 확인했다. 키오스크 근거 영역은 표시 높이 250px / 내용 722px이며 아래로 약 472px 스크롤한 뒤에도 세 개 행동 버튼이 모두 화면 안에 유지됐다. 결과 화면 행동/상세 컨트롤의 터치 높이도 48px 이상이었다. 얼굴 추천의 정확도나 실제 방문자 성능을 검증한 결과는 아니다.

## 클릭 시연

`/?sample=1&controls=1`에서 확인했다.

- 11자 이름 오류 → 다음 비활성화 → 정상 이름 입력
- 추천 조건 여자/남자/상관없음 → 표시 인원 4/4/8명, 초기값 상관없음
- AI 분석 실패 → 재시도 → 재촬영 → 결과 복구. 입력한 이름과 팀 유지
- 8개 캐릭터 선택 대화상자 → 다른 캐릭터 선택 → 직접 선택한 결과 문구
- 샘플 카드 등록 → 사원증 출력 화면 → 입사 완료
- 퇴근 기록 → 사진 생략 → 리포트 → 샘플 출력 → 완료
- 퇴근 기록 → 기념사진 → 다시 찍기 → 사진 포함 리포트 → 샘플 출력 → 완료
- 기념사진 전용 메뉴 → 자동 카드 확인 → 샘플 촬영 → 수정한 사진 확인 카드 → 인화 시연 → 완료
- 체험 기록 없음 시나리오 → 재확인만 제공, 리포트/사진 진행을 표시하지 않음
- 리포트 내부 스크롤: 내용 1008px / 표시 영역 590px, 하단까지 스크롤 가능. 출력 버튼이 풋터 위에 유지됨
- 완료 후 처음 화면에 이전 이름이 남지 않음
- 수집된 브라우저 경고·오류 로그 없음

```bash
preview_dir=$(mktemp -d /tmp/mirrorting-ui-preview.XXXXXX)
KIOSK_NFC=disabled KIOSK_PRINT=screen \
  KIOSK_DB_PATH="$preview_dir/kiosk.sqlite3" \
  .venv/bin/python scripts/run_kiosk.py --host 127.0.0.1 --port 8002
```

## 확인하지 않은 범위

브라우저 샘플과 UI 확인 결과다. 실제 방문자 촬영, 카메라 권한/조명, NFC 카드 쓰기·리더 연결, 감열 프린터의 종이 배출·절단·인쇄 품질, 실제 MirrorTing 기록 연동은 현장 확인이 필요하다. 물리 키보드의 한국어 IME와 실제 기기의 320px 화면도 이 점검으로 검증하지 않았다.
