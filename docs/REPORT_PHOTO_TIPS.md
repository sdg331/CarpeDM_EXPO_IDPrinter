# 사진을 함께 인쇄하는 체험 리포트 · 2026-10-12

퇴근 카드를 확인하고 MirrorTing 기록을 받은 뒤 사진을 선택적으로 촬영한다. 확인한 사진을 576도트 흑백 감열 리포트에 함께 인쇄한다. 사진 없이 진행하면 기록과 센터 팁만 인쇄한다. 전용 NFC 사진 카드는 별도 경로이며 체험 기록 없이 사진·소개 QR만 인화한다.

## 첨삭을 반영한 문구

사용자가 제공한 `4-Fit_MirrorTing_취업지원센터_검토자료_첨삭.docx`의 **빨간 글씨(FF0000)**를 확인했다. 취업지원센터 선생님이 선택한 1~5번 상황의 조언, 전화 응대 제안, 마지막 기록·체크리스트 조언을 요약했다. 첨삭이 없는 6~8번 상황에는 선생님 조언을 만들어 넣지 않는다. 원본 문서를 변경하지 않는다.

| 팁 | 첨삭 위치 | 요약 주제 |
|---|---|---|
| 01 | 상황 1 | 대상·목적·기준 자료·완성 시점 확인 |
| 02 | 상황 2 | 진행 상태·지연 원인·예상 영향·대안 사전 보고 |
| 03 | 상황 3 | 팀장에게 실수·현재 상황·해결 시간 보고 후 수정 부분 명시 |
| 04 | 상황 4 | 피드백 수용·이해한 수정 방향 설명·애매한 기준 질문 |
| 05 | 상황 5 | 팀장과 조율 여부 확인·겹친 업무 상황 보고·우선순위 확인 |
| 06 | 추가 제안 | 업무 전화 응대의 예의와 방법 연습 |
| 07 | 마지막 조언 | 업무 지시 메모·반복 업무 체크리스트 |

문구는 `backend/career_tips.py`에서 관리한다. 방문자 세션 ID를 시드로 7개 중 한 가지를 선택한다. 미리보기·인쇄·명시적 재시도·서버 재시작에서도 같은 세션은 같은 팁이며 다른 방문자 사이에는 반복될 수 있다. AI의 점수나 개인별 평가가 아니다. 2026-10-13 사용자 요청에 따라 화면과 종이에는 **TIP**·제목·조언만 표시한다. 센터명과 첨삭 요약 안내는 표시하지 않으며, 출처·note 데이터와 이 문서의 첨삭 이력은 유지한다. 공식 원문 인용이나 직무별 맞춤 추천으로 표시하지 않는다.

## 데이터·출력 계약

- `GET /api/reports/{sessionId}`는 실제 MirrorTing 기록과 별도로 로컬 `careerTip:{id,title,body,source,note}`를 추가한다. 기존 점수·미측정·참고 지표를 보존한다.
- 사진 없음: 기존 `POST /api/reports/print` JSON `{operationId,sessionId,reportId}` 유지.
- 사진 포함: `POST /api/reports/print-photo`, multipart `operationId`, `sessionId`, `reportId`, `frame`.
- 사진은 기존 8 MiB·1,200만 픽셀·JPEG/PNG/WebP 검증을 통과해야 한다. 잘못된 파일·다른 리포트 ID는 출력 작업을 시작하지 않는다.
- 두 출력 경로는 같은 `report_print` 작업·세션 중복 방지를 공유한다. 먼저 출력한 구성으로 한 번만 인쇄한다. 전송 후 결과 불명은 자동 재시도하지 않는다.
- 사진의 전체 프레임을 480×640 이내로 맞추며 늘이거나 자르지 않는다. 사진에만 디더링하고 글자·선은 선명한 1비트로 처리한다.
- 원본 사진·얼굴 벡터를 DB에 저장하지 않는다. 프런트 Blob/URL은 완료·취소·초기화·페이지 종료에 해제한다. 화면 출력 백엔드의 완성 리포트 PNG는 기존 메모리 보관 한도(기본 5분·8개)를 따른다. 외부 사진 업로드는 없다.
- 샘플 모드는 고정 캐릭터 사진·분석 예시·팁을 사용하고 실제 촬영·NFC·프린터를 실행하지 않는다.

## 실행·현장 확인

### 종이 리포트 상세 구성

2026-10-13: 종이는 큰 박스·검정 번호 띠·점수 막대를 없애고 얇은 점선과 여백으로 구성한다. 기념사진·방문 정보·오늘의 한 문장·종합 결과, 2열 4-Fit, 강점과 결말을 묶은 오늘 남은 장면, 연습과 행동 코칭을 묶은 다음 대화, TIP 순서로 읽힌다. 화면도 동일한 흐름으로 묶고 내부 스크롤과 하단 출력 버튼은 유지한다. 미측정·참고 지표·시선 점수 제외와 원본 피드백을 보존하며 점수나 해석을 생성하지 않는다. 사진의 전체 구도·디더링과 출력/API 계약은 유지한다.

프로젝트 루트에서 `KIOSK_NFC=disabled KIOSK_PRINT=screen .venv/bin/python scripts/run_kiosk.py --port 8012`로 화면 서버를 실행한다. `http://127.0.0.1:8012/?sample=1&controls=1`에서 **퇴근하기 → 리포트 확인 시연 → 기념사진 → 리포트 → 출력 시연**으로 확인한다. 샘플 없이 실제 리포트를 출력하려면 정상 NFC 등록과 MirrorTing 세션 연결이 먼저 필요하다.

실물 프린터에서는 얼굴의 명암, 머리·어깨의 잘림, 한글 가독성, 긴 리포트의 배출·절단·용지 소모, 명시적 재시도, 새 방문자 초기화를 확인한다. 소프트웨어 테스트 성공을 실물 인쇄 검증으로 취급하지 않는다.

## 인쇄 가독성·퇴근 처리 · 2026-10-13

출처 문구는 화면과 종이에서 제거한다. 감열지 글자는 최소 24px(203dpi 기준 약 8.5pt), 본문은 28px로 그리며 구분선은 2px로 출력한다. 576px 폭에서 줄바꿈·긴 피드백·사진 전체 구도를 검증한다. 실제 농도·번짐은 실물 프린터 인수 대상이다. 정상 리포트 출력 응답과 운영자의 printed 확인에서는 카드 UID 연결이 자동 해제된다. 실패/결과 불명에서는 카드 연결과 재시도 데이터를 유지한다.

## 밝고 흐린 사진의 출력 명암 보정

기념사진·퇴근 리포트의 사진에만 적용한다. 기존 main의 자동 명암 확장과 밝기 1.08 처리를 제거하고, EXIF 방향 보정 → 회색조 → 3×3 중간값 필터 → 전체 구도 유지 LANCZOS 크기 조정 → 감마 1.25 → 최종 도트 기준 샤픈 → Floyd–Steinberg 1비트 변환으로 처리한다. 기념사진은 512×640 이내, 리포트는 480×640 이내, 영수지는 기존 576도트 폭을 유지한다. 카메라 캡처, 글자·QR, 인쇄 전송 계층, 문구, 개인정보/NFC/세션 정책은 바꾸지 않는다.

운영자 환경변수 KIOSK_PHOTO_GAMMA=1.25 (허용 1.0–1.8)는 값이 클수록 중간톤을 진하게 한다. 1.0은 감마 중립이며 잘못된 값·NaN·무한대는 1.25로 돌아간다. 변경 후 서버를 재시작한다. 검정·흰색 끝점은 유지하며 밝은 값을 임의로 흰색으로 잘라내지 않는다. 날아간 원본 정보를 복구하거나 실물 품질을 보장하지 않는다. 거의 흰 배경에 점이 늘거나 저대비 사진의 분리가 약해질 수 있다.

검증: python -m pytest tests/test_thermal_photo.py tests/test_reports.py tests/test_souvenir.py tests/test_printing_usb.py -q. 선택적 python-escpos 설치 시 오프라인 인코더 비트 보존 검사도 실행한다. 실제 얼굴 없이 비교 그림 생성: python -m scripts.preview_thermal_photo --output /tmp/photo-tones.png. 이 명령은 파일만 만들며 인쇄하지 않는다.

적용 후 운영자가 동의한 사진으로 1장 시험 인쇄하여 화면 원본/종이의 밝기, 얼굴·머리 계조, 한글·QR, 배출/절단을 확인한다. 필요할 때만 감마를 1.25 → 1.4처럼 조금씩 올린다. 원본도 밝으면 조명/카메라 노출을 확인한다. 실제 프린터 DPI/유효 인쇄 폭, Pi 하드웨어, CUPS 드라이버의 추가 변환은 별도 검증 대상이다. 이 main 패치에는 다른 브랜치의 USB 밴드 전송이나 카드 없는 촬영 변경을 포함하지 않는다.
