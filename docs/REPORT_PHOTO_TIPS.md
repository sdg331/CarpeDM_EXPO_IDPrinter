# 사진을 함께 인쇄하는 체험 리포트 · 2026-10-12

퇴근 카드를 확인하고 MirrorTing 기록을 받은 뒤 사진을 선택적으로 촬영한다. 확인한 사진을 576도트 흑백 감열 리포트에 함께 인쇄한다. 사진 없이 진행하면 기록과 센터 팁만 인쇄한다. 전용 NFC 사진 카드는 별도 경로이며 체험 기록 없이 사진·소개 QR만 인화한다.

## 첨삭을 반영한 문구

사용자가 제공한 `4-Fit_MirrorTing_취업지원센터_검토자료_첨삭.docx`의 **빨간 글씨(FF0000)**를 확인했다. 취업지원센터 선생님이 선택한 1~5번 상황의 조언, 전화 응대 제안, 마지막 기록·체크리스트 조언을 요약했다. 첨삭이 없는 6~8번 상황에는 선생님 조언을 만들어 넣지 않는다. 원본 문서를 변경하지 않는다.

| 팁 | 첨삭 위치 | 요약 주제 |
|---|---|---|
| 01 | 상황 1 | 대상·목적·기준 자료·완성 시점 확인 |
| 02 | 상황 2 | 진행 상태·지연 원인·예상 영향·대안 사전 보고 |
| 03 | 상황 3 | 팀장에게 실수·현재 상황·해결 시간 보고 후 수정 부분 명시 |
| 04 | 상황 4 | 피드백 수용·이해한 수정 방향 설명·애매한 기준 질문 |
| 05 | 상황 5 | 팀장과 조율 여부 확인·겹친 업무 상황 보고·우선순위 확인 |
| 06 | 추가 제안 | 업무 전화 응대의 예의와 방법 연습 |
| 07 | 마지막 조언 | 업무 지시 메모·반복 업무 체크리스트 |

문구는 `backend/career_tips.py`에서 관리한다. 방문자 세션 ID를 시드로 7개 중 한 가지를 선택한다. 미리보기·인쇄·명시적 재시도·서버 재시작에서도 같은 세션은 같은 팁이며 다른 방문자 사이에는 반복될 수 있다. AI의 점수나 개인별 평가가 아니다. 팁 구역에 **동양미래대학교 취업지원센터**, **선생님 첨삭 내용을 짧게 정리했어요.**를 표시한다. 공식 원문 인용이나 직무별 맞춤 추천으로 표시하지 않는다.

## 데이터·출력 계약

- `GET /api/reports/{sessionId}`는 실제 MirrorTing 기록과 별도로 로컬 `careerTip:{id,title,body,source,note}`를 추가한다. 기존 점수·미측정·참고 지표를 보존한다.
- 사진 없음: 기존 `POST /api/reports/print` JSON `{operationId,sessionId,reportId}` 유지.
- 사진 포함: `POST /api/reports/print-photo`, multipart `operationId`, `sessionId`, `reportId`, `frame`.
- 사진은 기존 8 MiB·1,200만 픽셀·JPEG/PNG/WebP 검증을 통과해야 한다. 잘못된 파일·다른 리포트 ID는 출력 작업을 시작하지 않는다.
- 두 출력 경로는 같은 `report_print` 작업·세션 중복 방지를 공유한다. 먼저 출력한 구성으로 한 번만 인쇄한다. 전송 후 결과 불명은 자동 재시도하지 않는다.
- 사진의 전체 프레임을 480×640 이내로 맞추며 늘이거나 자르지 않는다. 사진에만 디더링하고 글자·선은 선명한 1비트로 처리한다.
- 원본 사진·얼굴 벡터를 DB에 저장하지 않는다. 프런트 Blob/URL은 완료·취소·초기화·페이지 종료에 해제한다. 화면 출력 백엔드의 완성 리포트 PNG는 기존 메모리 보관 한도(기본 5분·8개)를 따른다. 외부 사진 업로드는 없다.
- 샘플 모드는 고정 캐릭터 사진·분석 예시·팁을 사용하고 실제 촬영·NFC·프린터를 실행하지 않는다.

## 실행·현장 확인

프로젝트 루트에서 `KIOSK_NFC=disabled KIOSK_PRINT=screen .venv/bin/python scripts/run_kiosk.py --port 8012`로 화면 서버를 실행한다. `http://127.0.0.1:8012/?sample=1&controls=1`에서 **퇴근하기 → 리포트 확인 시연 → 기념사진 → 리포트 → 출력 시연**으로 확인한다. 샘플 없이 실제 리포트를 출력하려면 정상 NFC 등록과 MirrorTing 세션 연결이 먼저 필요하다.

실물 프린터에서는 얼굴의 명암, 머리·어깨의 잘림, 한글 가독성, 긴 리포트의 배출·절단·용지 소모, 명시적 재시도, 새 방문자 초기화를 확인한다. 소프트웨어 테스트 성공을 실물 인쇄 검증으로 취급하지 않는다.
