# 바로 시작하기 · 2026-10-12

현재 소프트웨어 테스트는 통과했다. Mac 화면 시연과 실제 Pi 운영은 다음처럼 실행한다. 기존 `.env`와 DB는 유지한다.

## Mac에서 화면 흐름 확인

현재 작업 폴더에는 `.venv`, 모델, 캐릭터 자산이 준비되어 있다.

```sh
cd "/Users/do_not_delay/Desktop/CarpeDM_EXPO_ID Printer/CarpeDM_EXPO_IDPrinter-complete"
.venv/bin/python scripts/preflight.py
KIOSK_NFC=disabled KIOSK_PRINT=screen .venv/bin/python scripts/run_kiosk.py --port 8012
```

이미 이 폴더의 서버가 8012에서 실행 중이면 다시 실행하지 않고 아래 주소를 연다. 포트 충돌 시 다른 포트를 지정하며, 다른 서버를 임의로 종료하지 않는다.

| 주소 | 확인할 내용 |
| --- | --- |
| <http://127.0.0.1:8012/?sample=1&controls=1> | 고정 샘플로 출근·직접 선택·퇴근, 오류/재시도 시연 |
| <http://127.0.0.1:8012/?preview=1> | 카메라 권한 허용 후 실제 사진·로컬 AI·디지털 사원증 |
| <http://127.0.0.1:8012/static/ui-preview.html> | 구현된 32개 화면과 상태를 직접 선택 |

샘플은 실제 카메라·NFC·인쇄를 실행하지 않는다. 웹 미리보기는 실제 카메라/AI를 사용하지만 카드 등록·종이 출력은 진행하지 않는다. 현재 Mac 설정으로 기본 `/`에서 실물 카드 등록을 할 수는 없다.

출근 샘플 순서: 출근 → 팀 → 이름 → 촬영 → 추천 결과 → 다른 캐릭터 고르기 → 사원증 만들기 → 카드 연결 시연 → 출력 시연 → 완료. 원하는 캐릭터를 고르지 않고 추천 결과로 진행해도 된다. 퇴근에서는 사진 없이 리포트를 볼 수 있다.

## 실제 Raspberry Pi에서 시작

Pi에 저장소·Python 환경·모델을 준비하는 명령은 [README](../README.md)의 설치 절차를 따른다. 아래 명령은 **Pi의 저장소 루트**에서 실행한다.

1. `.env`의 `KIOSK_NFC=pcsc`, `KIOSK_PRINT=escpos`를 설정한다. `KIOSK_ESCPOS_VENDOR`/`KIOSK_ESCPOS_PRODUCT`는 `lsusb`로 확인한 실제 값을 사용한다. 리더와 프린터 전원·USB·권한·PC/SC 서비스도 확인한다.
2. MirrorTing 리포트를 사용하려면 [연결 안내](../integrations/mirrorting/README.md)에 따라 상대 서버에 모듈을 적용하고 두 서버의 토큰과 주소를 설정한다. 토큰은 브라우저나 공유 화면에 표시하지 않는다.
3. 기동 전 점검 후 서버를 실행한다.

```sh
.venv/bin/python scripts/preflight.py --hardware
.venv/bin/python scripts/run_kiosk.py --host 127.0.0.1 --port 8002
```

4. Pi Chromium에서 <http://127.0.0.1:8002/>를 열고 카메라 권한을 허용한다. 800×1280 화면·터치·물리 키보드의 한글 입력을 확인한다. 서버는 worker 1개를 사용한다.

`preflight --hardware`는 리더와 출력 설정을 검사하며 촬영·인쇄하지 않는다. 통과해도 종이 출력·커터·용지 상태와 전체 체험 검증은 별도로 필요하다.

## 전시 시작 전 확인할 흐름

- 실제 사진 촬영 → 추천/직접 선택 → 카드 등록 → 종이 사원증을 각각 확인한다. 05번 안경과 8명의 정수리·얼굴 구도가 출력물에서도 보이는지 확인한다.
- 같은 카드를 다른 방문자에게 재사용하고 이전 이름·사진·리포트가 남지 않는지 확인한다.
- MirrorTing 실제 체험 → 퇴근 카드 → 실제 기록 조회 → 종이 리포트를 확인한다. 퇴근 기념사진은 화면에만 포함되고 현재 종이 리포트에는 인쇄되지 않는다.
- 카메라 권한 거절, 리더 분리, 프린터 통신 단절, 기록 없음 상황에서 복구 동선을 확인한다. 출력 결과가 불명확하면 [운영 절차](OPERATIONS.md)에 따라 실제 출력물과 대기열을 확인한다. DB 삭제나 새 작업으로 재출력하지 않는다.
- 연속 방문자 체험과 전원 재인가를 확인하고 장비·설정·문제·복구 결과를 기록한다.

현재 Mac 점검으로 이 현장 항목들이 통과했다고 판단하지 않는다. 캐릭터 매칭은 추천이며 닮음 정확도가 검증된 기능은 아니다. 결과에서 원하는 캐릭터를 직접 고를 수 있다.

## 전용 카드 기념사진

[설정·카드 UID 확인·인화 운영](SOUVENIR.md)을 따른다. 실제 소개 주소와 전용 카드 UID를 `.env`에 등록하고 `preflight.py --hardware --souvenir`로 점검한 뒤 서버를 재시작한다. 샘플 HOME의 **기념사진만 남기기**에서 별도 흐름을 확인할 수 있다. 사진은 이름 입력·AI 분석·MirrorTing 체험 없이 감열 인화한다. 실제 QR 주소와 장치 검증이 필요하다.
