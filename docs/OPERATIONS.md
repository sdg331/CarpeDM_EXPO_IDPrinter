# 실행과 현장 운영

이 문서는 통합 버전의 운영 절차다. 실제 Raspberry Pi·NFC·프린터 검증 결과는 별도 기록한다.

## 시작 전

1. `.env.example`을 `.env`로 복사하고 실제 장치/서비스 값만 설정한다.
2. `.venv/bin/python scripts/preflight.py`로 의존성·모델·한글 폰트를 확인한다.
3. Pi에서는 `--hardware`를 추가해 PC/SC 리더와 출력 설정을 확인한다. 이 명령은 얼굴 촬영이나 인쇄를 하지 않는다.
4. `.venv/bin/python scripts/run_kiosk.py`로 단일 worker 서버를 시작한다.
5. Pi의 Chromium에서 `http://127.0.0.1:8002/`를 연다. 브라우저 카메라 권한과 화면/터치/한글 입력은 실제 장치에서 확인한다.
6. A/B 각 1회 발급, 카드 재사용, MirrorTing 체험 후 퇴근 리포트까지 실제 동선을 확인한다.

Mac에서 포트 충돌이 있으면 `--port 8012`처럼 사용하지 않는 포트를 지정한다. 다른 프로젝트의 서버를 임의로 종료하지 않는다.

## 출력 상태의 의미

- `preview`: 메모리에 만든 출력 미리보기. 종이가 출력되지 않았다.
- `submitted`: 장치/대기열에 전송됨. 장치가 종이 배출 완료를 보증한 상태는 아니다.
- `confirmed`: 운영자가 실제 출력물을 확인해 결과 불명 작업을 해소함.
- `UNKNOWN_OUTCOME`: 일부 데이터가 전송되었을 수 있어 재출력 여부를 자동 판단할 수 없음.

`KIOSK_PRINT=screen`은 미리보기만 제공한다. 현재 ESC/POS/CUPS 경로는 전송 결과와 물리적 배출 완료를 구분한다. 용지 부족·걸림을 장치가 확실히 보고하지 않으면 해당 상태를 추정 표시하지 않는다.

## 출력 결과 불명 복구

1. 관람객을 잠시 대기시키고 실제 출력물과 장치 대기열을 확인한다.
2. 결과 불명 오류 화면의 `운영 확인용 작업 ID`를 그대로 사용해 상태를 조회한다. 사원번호나 MirrorTing 세션 번호와 혼동하지 않는다. 상태 확인 중 또는 조회 실패 후에도 같은 작업 ID가 유지된다.

```sh
.venv/bin/python scripts/kiosk_admin.py operation OPERATION_ID
```

3. 실제 배지/리포트가 나왔다면:

```sh
.venv/bin/python scripts/kiosk_admin.py resolve-print OPERATION_ID --outcome printed --confirm-checked
```

4. **출력되지 않았고 대기열에도 남아 있지 않음을 확인한 경우에만**:

```sh
.venv/bin/python scripts/kiosk_admin.py resolve-print OPERATION_ID --outcome not_printed --confirm-checked
```

5. 키오스크의 작업 상태 다시 확인을 누른다. `not_printed`는 자동으로 인쇄하지 않으며 동일 작업의 명시적 재시도를 허용한다.

브라우저 새로고침이나 DB 삭제로 출력 작업을 우회하지 않는다. 재부팅 도중 실행 중이던 출력도 불명 상태로 복구된다. 만료되거나 다른 관람객에게 재할당된 세션은 다시 출력하지 않는다.

## 사진·방문자 정보

- 원본 촬영 프레임은 처리 후 메모리에서 해제한다.
- B 결과는 기본 10분, 출력 미리보기는 기본 5분 동안만 메모리에 유지한다.
- 서버 재시작으로 이미지가 없어지면 재촬영한다. 이미 출력 여부가 불명확한 작업에는 재촬영으로 우회하지 않는다.
- 이름·카드 UID·MirrorTing 접근 토큰은 기본 24시간 후 삭제/익명화한다. 운영 일정에 맞게 `.env`에서 기간을 정한다.
- 작업 ID와 상태 등 최소 이력은 중복 출력 방지를 위해 유지한다.
- 이미 만료된 개인정보를 운영자가 정리하려면:

```sh
.venv/bin/python scripts/kiosk_admin.py purge-expired --confirm
```

원본 DB나 공유 전시 데이터를 테스트용 DB로 사용하지 않는다. DB와 `.env`를 Git, 클라우드 동기화 폴더, 공개 다운로드 경로에 두지 않는다.

## 다른 장비의 MirrorTing 연결

키오스크 방문객 API는 localhost 접속만 허용한다. 다른 장비에서 접근할 수 있는 API는 인증된 `/api/integrations/mirrorting/*`뿐이다. Pi Chromium은 계속 `127.0.0.1`로 접속한다. `KIOSK_HOST=0.0.0.0`으로 bridge를 열 때에도 전시장 신뢰 네트워크와 방화벽으로 상대 서버의 접근 범위를 제한한다. 역방향 프록시를 추가해 원격 요청이 localhost처럼 보이게 만들면 이 제한을 우회할 수 있으므로 같은 경로 제한을 프록시에서도 적용한다.

## Pi 자동 시작

`deploy/mirrorting-kiosk.service.example`은 systemd 설정 예시다. 실제 설치 경로와 실행 사용자, USB 권한, `.env` 권한을 확인한 뒤 설치한다. 이 저장소의 개발 실행은 시스템 서비스를 자동 설치하거나 활성화하지 않는다.

서비스는 worker 1개를 사용한다. B 프로필과 출력 미리보기는 프로세스 메모리에 있으므로 worker를 늘리려면 이미지 저장 구조와 동시 처리 검증이 먼저 필요하다.

브라우저 자동 시작 설정은 실제 Pi 데스크톱 세션에서 확인한다. 최종 인수 항목에는 전원 재인가 후 서버·브라우저·카메라·터치·한글 입력·NFC 복구가 포함된다.

## 종료 전

진행 중이거나 결과가 불명확한 출력을 먼저 확인하고, 서버를 정상 종료한다. 다음 기동 시 실제 카드·용지·카메라 상태부터 확인한다. 확인한 릴리스 커밋, 설정 변경, 장애와 복구 결과를 현장 기록에 남긴다.
