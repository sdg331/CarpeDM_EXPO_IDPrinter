# 기념사진 촬영·인화

## 현재 운영 · 2026-10-16

카드 없는 촬영·인화를 유지한다. 사진 전용 인화와 사진 포함 퇴근 리포트는 사진 다음에 응원 문구와 CarpeDM 도장을 인쇄하며, 소개 URL이 설정된 경우 QR도 유지한다. 출력 전송 실패 시 완성된 감열 이미지를 로컬 비공개 DB에 잠시 보관하고 기존 일괄 복구로 처리한다. [전체 업데이트와 검증 범위](qa/FINAL_KIOSK_2026-10-16.md)를 먼저 확인한다.

## 카드 없는 촬영 도입 기록 · 2026-10-13

HOME의 **사진만 찍기** → 카메라 즉시 시작 → 촬영 → 사진 확인/다시 찍기 → 인화.
카드·이름·팀·AI 분석·스마트미러 체험을 요구하지 않는다. 촬영 버튼은 실제 카메라가 준비되면 활성화된다. 사진 아래에는 4-Fit MirrorTing 작품 소개와 동양미래대학교 CarpeDM 정보를 인쇄한다.

`KIOSK_SOUVENIR_QR_URL`이 비어 있어도 촬영·인화한다. 실제 공개 소개 주소가 설정되어 있으면 QR도 포함한다. 전용 UID는 이 경로에서 필요하지 않다. 아래 전용 카드 경로는 기존 퇴근 카드 호환을 위한 이력이다.

사진은 노이즈 완화 → Lanczos 축소 → 명암·윤곽 보정 → 1비트 사진 디더링으로 처리한다. 프린터에는 원래 해상도를 유지한 128행 구간으로 전송한다. 문자·QR은 사진 디더링을 적용하지 않는다. 실제 종이 농도·용지 상태·인쇄 헤드 상태는 실물을 확인한다.

출근·퇴근·홈 진입은 이전 화면의 카드 인식 결과를 지우고 진행 중 카드 읽기를 취소한다. 등록된 카드와 체험 기록은 퇴근 조회에 필요한 데이터이므로 이 초기화로 삭제하지 않는다.

## 이전 전용 카드 경로 · 2026-10-12

체험에 참여하지 않는 관람객도 전용 운영 카드로 사진 한 장을 남길 수 있다. 사진은 흑백 감열 용지에 인화하고 QR은 MirrorTing 소개·팀 사이트로 연결한다. 사진 다운로드 서버나 외부 사진 전송은 사용하지 않는다.

## 사용 흐름

HOME의 **기념사진만 남기기** → 자동 카드 읽기 → 전용 카드 태그 → 촬영 → 사진·소개 QR 확인 → 인화 → 전용 카드 반납.

일반 퇴근의 카드 확인에서도 전용 카드를 읽으면 같은 촬영 경로로 간다. 일반 사원증은 기념사진 메뉴에서 사용할 수 없고, 전용 카드는 입사 카드로 등록할 수 없다. 카드 UID는 방문자 화면에 표시하지 않는다. 사진 전용 경로에는 이름 입력·캐릭터 매칭·MirrorTing 기록 조회가 없다.

퇴근 리포트도 선택한 기념사진을 체험 기록과 함께 인쇄한다. 전용 카드 경로는 체험 기록 없이 사진과 소개 QR만 인화한다. [체험 리포트·센터 팁](REPORT_PHOTO_TIPS.md).

## 운영 설정

실제 소개 사이트 주소와 전용 카드 UID를 확정한 뒤 `.env`에 등록한다. 현재 예제의 두 값은 비어 있으며, 임의의 사이트로 연결하거나 가짜 QR을 인쇄하지 않는다.

```dotenv
KIOSK_SOUVENIR_CARD_UID=
KIOSK_SOUVENIR_QR_URL=
```

UID 확인은 다른 프로세스와 리더가 충돌하지 않도록 **키오스크 서버를 중지한 뒤** 저장소 루트에서 실행한다.

```sh
KIOSK_NFC=pcsc .venv/bin/python scripts/kiosk_admin.py read-card
```

이 명령은 태그한 카드의 UID를 로컬 운영 터미널에 출력한다. 결과의 `KIOSK_SOUVENIR_CARD_UID=…` 값을 `.env`에 넣는다. QR 주소는 본인이 운영하는 실제 HTTP(S) 소개 주소를 넣는다. 인증 정보·공백·잘못된 포트가 포함된 주소와 UTF-8 200바이트를 초과한 주소는 거부한다. 짧은 공개 주소를 사용한다.

Pi의 실제 리더·프린터는 기존 설정 안내를 따르고 아래처럼 점검한다.

```sh
.venv/bin/python scripts/preflight.py --hardware --souvenir
.venv/bin/python scripts/run_kiosk.py --host 127.0.0.1 --port 8002
```

설정을 바꾼 뒤 서버를 다시 시작한다. `screen` 출력은 이미지 미리보기이고 실물 인화가 아니다. `escpos`/`cups` 성공은 장치 제출이며 용지 배출·커터 완료를 뜻하지 않는다.

## 개인정보와 출력 보호

- 촬영 권한은 서버 메모리에 10분, 최대 8개다. 원본 사진·얼굴 벡터·이름·방문자 세션을 DB에 만들지 않는다. 업로드는 기존 이미지 크기·형식 검사를 통과해야 한다.
- 사진은 촬영 확인/명시적 재시도를 위해 브라우저 메모리에 유지하며 완료·취소·초기화·페이지 종료 시 해제한다. 화면 출력 백엔드의 인화 미리보기는 최대 5분 보관하고 HOME 복귀 때 삭제를 요청한다. 서버 종료 시 메모리 저장소를 비운다.
- QR은 카드 확인 당시 서버 설정 주소를 고정한다. 촬영 프레임은 로컬 키오스크로만 보내고 소개 QR에는 사진 URL·이름·UID·촬영 권한이 들어가지 않는다.
- 촬영 권한마다 서버가 고정한 하나의 출력 작업 ID를 사용한다. 반복 탭·동시 요청·재시작 뒤 재전송이 새 인화를 만들지 않는다. 사진 디더링과 별개로 QR은 정수 배율·흰 여백·선명한 모듈을 유지한다. 기존 [OpenCV QR encoder](https://docs.opencv.org/4.x/d2/dbb/classcv_1_1QRCodeEncoder.html)를 사용한다.
- 결과 불명 작업은 재출력을 잠그고 새 사진 카드 승인도 막는다. 운영자는 실제 종이/대기열을 확인한 뒤 기존 `kiosk_admin.py resolve-print` 절차로 해소한다. 서버가 재시작되어 촬영 권한·사진이 사라졌다면 해소 후 새 카드 확인과 촬영이 필요하다. DB 삭제로 우회하지 않는다.

## 확인 방법

샘플: `http://127.0.0.1:8012/?sample=1&controls=1` → 기념사진만 남기기. 샘플은 캐릭터 사진을 사용하고 실물 NFC·촬영·인화를 실행하지 않으며 실제 QR 대신 설정 안내를 표시한다.

고정 화면: `/static/ui-preview.html?screen=souvenirReview`, 카드·촬영·인화·결과도 화면 목록에서 선택한다.

실물 인수: 전용 카드/일반 카드 → 취소·재촬영 → 정상 인화 → 휴대폰 QR 스캔 → 프린터 단절·결과 불명 복구 → 다음 방문자 초기화를 확인한다. 감열지 명암·급지·절단·QR 스캔 거리는 실제 Pi/프린터에서 조정한다.

## 사진·글씨가 흐릴 때 · 2026-10-16

기념사진과 퇴근 사진은 같은 `thermal_photo()`를 사용한다. 원격의 최신 감마 보정을 유지한다. 방향 보정·회색조 → 3×3 중간값 필터 → 전체 구도 유지 LANCZOS 축소 → 감마 1.25 → 최종 크기 윤곽 보정 → Floyd–Steinberg 순서다. 앞서 로컬에서 비교한 대비 1.2배 방식 대신 밝은 얼굴의 계조를 보존하는 최신 처리로 통합했다. 사진 이후에는 크기를 바꾸지 않으며 글씨와 QR은 사진 보정 대상이 아니다. 운영 설정 `KIOSK_PHOTO_GAMMA`는 1.0–1.8 범위이며 실물 적합성은 별도 확인한다.

글씨까지 함께 연하면 사진 처리만으로 원인을 설명할 수 없다. 아래 비교지는 같은 사진의 기존/개선 처리를 실제 인쇄 크기(최대 512×640도트)로 출력하고 위쪽에 1·2·4도트 선과 검정 영역을 표시한다. 기본 이미지는 동봉된 캐릭터 샘플이며 방문자 사진을 가져오거나 저장하지 않는다.

저장소 루트에서 이미지 생성과 회귀 테스트를 실행한다.

```sh
.venv/bin/python scripts/print_photo_check.py
.venv/bin/python -m pytest tests/test_reports.py tests/test_souvenir.py -q
```

결과는 Git 제외 경로 `.preview/print-quality.png`다. 직접 준비한 로컬 사진으로 비교하려면 `--photo /path/to/test-photo.jpg`를 사용한다. 이 경우 비교지에 해당 사진이 저장되므로 본인이 제공한 테스트 사진만 사용하고 확인 후 삭제한다.

Pi에서 기존 USB ID·전용 전원 설정을 확인하고, 키오스크 서버를 중지한 상태에서 한 번 출력한다. 실행 중인 서버와 프린터를 동시에 사용하지 않는다.

```sh
KIOSK_PRINT=escpos .venv/bin/python scripts/print_photo_check.py --print
```

이 명령은 `.env`의 기존 USB ID를 사용하고, 프린터 설정·농도·속도를 변경하지 않는다. PNG를 브라우저/문서 인쇄의 페이지 맞춤으로 출력하면 점 패턴이 재조정될 수 있으므로 비교지는 위 직접 출력 경로로 확인한다. ESC/POS 이미지 전송은 현재 라이브러리 기본값이 고밀도이며, 저밀도는 이미지를 늘린다([python-escpos 공식 문서](https://python-escpos.readthedocs.io/en/latest/user/methods.html#escpos.escpos.Escpos.image)).

현장에서는 다음 순서로 구분한다.

1. 프린터 자체 테스트 페이지도 연한지 확인한다. 정확한 실행 방법은 해당 모델의 설명서를 따른다. 자체 테스트까지 연하면 감열지의 발색면·상태, 프린터 전용 12V 5A 전원과 커넥터, 헤드·롤러 상태를 확인한다. 전원 기준은 [프로젝트 하드웨어 문서](HARDWARE_ENCLOSURE_2026-09-30.md)를 따른다.
2. 자체 테스트는 선명하지만 비교지 선·글씨도 연하면 실제 실행 중인 저장소와 USB 직접 출력/CUPS 드라이버·배율 경로를 확인한다. 이 Mac의 `screen` 미리보기는 Pi의 실물 출력 증거가 아니다.
3. 선·글씨는 선명하고 사진만 흐리면 같은 종이에서 A/B의 눈·안경·입술 윤곽과 머리카락의 검정 뭉침을 비교한다. 촬영 원본의 초점·흔들림·얼굴 크기도 확인한다. 작은 얼굴이나 초점이 나간 원본의 세부 묘사는 인쇄 보정으로 복원되지 않는다.
4. 헤드 청소나 농도·속도 변경은 해당 모델의 설명서·제조사 도구로 진행한다. ZTP-80USL2의 농도 명령을 확인하지 못했으므로 다른 프린터의 가열/속도 명령을 보내지 않는다. 프린터 제출 후 오류가 났다면 종이를 확인한 뒤 재실행한다.

실물 농도·번짐·급지·절단은 이 비교지와 실제 프린터로 확인해야 한다. 자동 테스트는 명암 구분, 전체 구도·회전, QR 픽셀 보존과 디코딩, 중복 인화 방지까지만 검증한다.

## GitHub 수정본을 Pi에 적용

아래는 사진 비교 도구 배포 당시 기록이다. 현재 MediaPipe 환경 설치와 최종 검사 결과는 [2026-10-16 안내](qa/FINAL_KIOSK_2026-10-16.md)를 우선한다.

기존 IDPrinter 저장소에서 진행한다. 다른 Raspberry Pi 저장소나 스마트미러 저장소에 실행하지 않는다. 진행 중인 방문자·출력 작업이 끝난 뒤 기존 서버 터미널에서 Ctrl+C로 중지한다. 서비스로 실행 중이라면 실제 서비스 관리 방식으로 중지한다.

```sh
git remote -v
git status --short
git fetch origin
git switch codex/nfc-smart-mirror-link
git pull --ff-only origin codex/nfc-smart-mirror-link
git log -1 --oneline
KIOSK_PRINT=escpos .venv/bin/python scripts/preflight.py --hardware
```

원격은 `https://github.com/sdg331/CarpeDM_EXPO_IDPrinter.git`인지 확인한다. 로컬 변경·다른 이력으로 Git 명령이 중단되면 다음 명령으로 진행하지 않고 변경분을 먼저 보존한다. 기존 `.env`와 세션 DB는 덮어쓰지 않는다. 이번 비교 도구에는 새 의존성이 없다.

서버가 중지된 동안 위 비교지 인쇄 명령으로 1장 확인한 뒤 다시 시작한다.

```sh
KIOSK_PRINT=escpos .venv/bin/python scripts/run_kiosk.py --host 127.0.0.1 --port 8002
```

브라우저에서 `http://127.0.0.1:8002/`를 새로고침하고 기념사진을 확인한다. 서비스 운영 환경은 위 개발 서버 대신 기존 서비스 재시작 절차를 사용한다.

## 응원 문구와 팀 도장 · 2026-10-16

전용 카드 사진과 사진 포함 퇴근 리포트는 `사진 → 응원 문구 6줄 → 여백 → CarpeDM 도장`을 같은 렌더러로 인쇄한다. 도장은 흰 바탕·진한 검정 글씨·8도트 사각 테두리다. `CarpeDM`은 78px, 아래 `오늘의 당신을 응원합니다`는 25px이며 거친 질감이나 가는 장식 선은 없다. 원본 사진의 전체 구도와 사진에만 적용하는 디더링, 기존 소개 QR을 유지한다.

이전 메모리 전용 출력 설명의 변경: 장치 접근 **전**에 완성한 감열 출력 PNG를 로컬 SQLite `print_payloads`에 임시 보관한다. 원본 촬영 프레임을 저장하는 기능은 아니다. 출력 전송/미리보기 성공 또는 운영자의 실물 출력 확인 시 제거하고, 미해결 이미지는 기본 24시간 보관기간에 따라 시작 시/15초 주기로 제거한다. 외부 전송·공개 이미지 조회 API는 없다. DB/WAL/SHM은 Git 제외 대상이며 서버 재시작 후에도 미해결 출력 이미지를 복구할 수 있다.

출력 오류 및 `SOUVENIR_PRINT_PENDING` 화면의 **미출력 건 한 번에 출력**에서 용지와 장치 대기열을 확인하고 처리할 건을 선택한다. `미출력 확인 · 한 번에 출력`은 같은 작업 ID와 저장된 이미지를 순서대로 재사용한다. 이미 종이가 나온 결과 불명 건은 `선택한 건 이미 출력됨`으로 차단만 해제한다. 정상 처리된 건·진행 중인 건·회수된 카드 세션은 다시 출력하지 않는다. 프린터 오류가 다시 나면 배치를 중단하며 나머지 건은 원래 상태를 유지한다.

이전 버전/보관기간 경과로 이미지가 없는 건은 `이전 이미지 없음`으로 표시한다. 미출력을 확인하면 차단을 해제하되, 실제 출력했다고 표시하지 않는다. 현재 화면에서 재시도하거나 카드를 다시 태그하고 다시 촬영해야 한다. 존재하지 않는 사진을 복원할 수는 없다.
