# 사원증 발급 키오스크 하드웨어·함체 논의 통합본

기준일: 2026-09-30

이 문서는 사원증 발급 키오스크/감열 프린터 관련 대화에서 확정된 내용, 현재 설계 방향, 폐기된 안, 고장/리스크, 남은 검증을 한곳에 모은 하드웨어 기준 문서다.

상태 표기:
- **CONFIRMED**: 현재 확정
- **CURRENT DIRECTION**: 현재 채택 방향이나 세부 치수/고정부는 추가 검증 필요
- **TBD**: 미결
- **SUPERSEDED**: 이전 안이며 현재 사용하지 않음
- **ISSUE**: 현재 해결해야 하는 문제

## 1. 제품 역할

- 작품 전체: **4-Fit MirrorTing**
- 가상 회사: **MIRRORTING WORKS**
- 장치 역할: 관람객의 체험 시작/등록, NFC 사원증 연결, 프로필 또는 리포트의 물리 출력
- 스마트미러와 별도 장치지만 NFC/세션 흐름으로 연결
- 관람객에게 NFC 카드를 증정하지 않고 **반복 회수·재사용**한다.

### 프린터 치수 주의

대화 중 프린터 실측값으로 “가로 115 mm × 높이 130 mm × 깊이 850 mm”가 한 번 기록되었으나 깊이 850 mm는 오기 가능성이 높다. 기존 설계 자료에서는 약 **114.8 × 131.8 × 86 mm**를 사용했다.

최종 프린터 바스켓/출력구 STL을 확정하기 전에는 실물 깊이, 전면 플랜지, 용지 덮개가 열릴 때 필요한 공간을 다시 측정한다.

## 3. 최신 전면/외관 방향

**CURRENT DIRECTION**

- 세로형, 무광 블랙
- 화면을 중심으로 여백을 과도하게 만들지 않고 가볍고 고급스럽게 보이도록 구성
- 상단 중앙에 Camera Module 3
- 화면 좌우/상단 주변에 COB LED를 배치하되 LED 알갱이가 직접 보이지 않도록 확산재 사용
- 프린터 본체는 전면에서 숨기고 **용지 배출구만 노출**
- NFC는 최신 논의 기준 **오른쪽 배치**가 우선이며, 완전히 숨기지 않고 의도적으로 보이거나 약간 돌출되어도 허용
- NFC 케이블은 외부에서 지저분하게 보이지 않도록 내부 라우팅
- 전면 물리 키보드 및 키보드 트레이 없음
- 후면/내부는 유지보수성과 배선을 우선

이전의 “하단 좌측 프린터 + 하단 우측 NFC + 하단 키보드 트레이” 고정 레이아웃은 최신 방향으로 대체한다.

## 4. 프린터 통신·전원

### 전원 — CONFIRMED

- ZTP-80USL2는 **12V 5A 별도 전원**을 사용한다.
- Raspberry Pi 5에서 프린터 전원을 직접 공급하지 않는다.
- Pi 5는 공식 27W USB-C 전원을 유지한다.

### 통신 — CURRENT DIRECTION

1순위는 **USB**, RS232는 USB 수리가 어렵거나 현장 안정성 문제가 확인될 때의 대체 경로다.

- 평상시 USB와 RS232를 동시에 연결할 필요는 없다.
- 한 가지 통신 경로를 기준으로 검증해 장애 원인을 단순화한다.
- 프린터 USB 보드 핀은 대화 기준 **GND / D+ / D- / VUSB**
- PH2.0 4핀 계열 하네스/USB-A 데이터 피그테일이 필요하다.

## 5. 현재 프린터 USB 문제

**ISSUE — 2026-09-30**

- 프린터 USB 연결부가 파손됨
- 잘못된 규격의 케이블을 2개 구매한 상태
- 기존 커넥터가 쉽게 빠지지 않음
- 납땜을 처음 시도했고 수리가 성공하지 않음
- 무리한 추가 납땜보다 **정확한 하네스/커넥터 확보 또는 수리 가능한 전자부품점/작업자에게 맡기는 방향**이 우선

이 문제 때문에 전체 키오스크 제작을 멈출 필요는 없다.

프린터 없이 먼저 진행 가능한 작업:
- Pi 5 + 디스플레이 구동
- Camera Module 3
- UI/UX
- NFC 소프트웨어
- 화면 베젤/상부 함체
- LED 확산 구조
- 내부 배선 경로
- 프린터 바스켓 외부 치수 설계

단, 최종 출고/전시 승인 전에는 실제 ZTP-80USL2로 출력, 자동 커터, 중복 출력 방지, 용지 부족/걸림 상황을 반드시 검증한다.

## 6. 용지 교체와 프린터 장착 구조

### SUPERSEDED

- 숨은 경첩 + push latch 방식은 사용하지 않는다.

### CURRENT DIRECTION

프린터는 **바구니/크래들(basket/cradle) 형태의 모듈**로 잡는다.

목표:
- 본체는 관람객 시야에서 최대한 숨김
- 배출구만 전면 노출
- 정비 시 프린터 모듈을 쉽게 들어 올리거나 빼서 상단 용지 덮개에 접근
- 복잡한 힌지/래치 없이 빠른 용지 교체
- 전원·USB 케이블에 스트레인 릴리프와 충분한 여유 길이 확보
- 용지 덮개가 완전히 열리는 각도/공간 확보

정확한 고정 방식(볼트, 스냅, 단순 가이드 등)은 실물 치수 확인 후 결정한다.

## 7. NFC 방향

**CONFIRMED / CURRENT DIRECTION**

- 장치: ACR1252U
- 카드 자체는 관람객에게 제공하지 않고 회수해 재사용
- 최신 배치 선호는 **오른쪽**
- 완전 매립보다 사용자가 “여기에 태그한다”는 것을 즉시 이해할 수 있는 형태가 우선
- 약간 돌출되거나 별도 태그 패드처럼 보여도 허용
- 케이블은 내부로 바로 숨겨 상단/후면에 선이 보이지 않게 처리
- 금속 차폐 구조는 NFC 감도에 영향을 줄 수 있으므로 실제 카드 태그 테스트 필수

과거의 “하단 우측 사선면 1.5~2 mm 비금속 창 뒤 완전 매립”은 가능한 참고안이지만 최신 우선안은 아니다.

## 8. LED 조명

- 5V COB LED 사용
- 보유 ON/OFF 컨트롤러 활용
- LED 점/선이 그대로 보이지 않도록 반투명지 또는 확산재를 사용
- 화면 좌우와 상단 카메라 주변을 중심으로 조명 역할을 주는 방향
- “ㄷ자 몇 조각” 같은 고정 분할 형태보다 실제 밝기/열/배선 결과를 보고 길이를 정한다.
- 화면을 비추거나 얼굴 촬영 보조 역할을 하기 때문에 너무 짧게 잡지 않는다.
- 긴 LED 스트립을 Pi USB에서 무리하게 직접 구동하지 않는다.
- 전원선과 영상/데이터선을 가능하면 분리해 노이즈·정비 문제를 줄인다.

## 9. USB 허브

**CURRENT DIRECTION**

- 기본은 Pi 5에 터치, NFC, 프린터 등을 직접 연결
- 포트 수/전력/배선 때문에 필요할 때만 **유전원 USB 허브** 사용
- 이전에 ipTIME UH508, NEXTU NEXT-327U3, 8포트 허브 등이 후보로 검토됨
- 허브를 함체 필수 부품으로 고정하지 않는다.

## 10. 전원/배선 구조

권장 분리:
- Pi 5 → 공식 27W USB-C
- 프린터 → 12V 5A
- 디스플레이 → 보유 전원
- COB LED → 별도 5V/컨트롤러

배선 설계 원칙:
- 전원과 데이터 경로를 구분
- HDMI/터치 USB/CSI 케이블의 최소 굽힘 반경 확보
- 디스플레이를 세로로 설치해도 후면 포트가 꺾이지 않도록 공간 확보
- 프린터 서비스 시 케이블이 잡아당겨지지 않도록 여유 길이/고정점 확보
- 벨크로 케이블타이 사용
- 후면 포트와 전원 어댑터 접근성을 유지
- AC 16A C13 계열 전원 케이블도 조달 항목으로 논의됨

## 11. 3D 프린팅/함체

### 현재 제작 장비

- Bambu Lab A1
- 빌드 볼륨 256 × 256 × 256 mm
- 검은색 필라멘트 보유

따라서 약 300 × 150 × 520 mm 본체는 한 번에 출력하지 않고 분할한다.

### 최신 출력 순서

1. **디스플레이를 감싸는 베젤/프레임부터 출력**
2. 실제 디스플레이 삽입 및 HDMI/USB 케이블 간섭 확인
3. 상단 Camera Module 3 + LED 구조
4. 하단/측면 NFC 구조
5. 프린터 배출구 + basket/cradle
6. 내부 Pi/전원/케이블 브래킷
7. 후면 서비스 구조
8. 전체 조립 후 최종 장식/마감

프린터가 수리되지 않았더라도 1~4단계는 진행 가능하다.

### 이전에 제안된 출력 설정

다음은 초안 프린트 프로파일로 논의된 값이며 최종 고정값은 아니다.

- 0.4 mm 노즐
- 레이어 0.24~0.28 mm
- 벽 4겹
- 인필 약 15%
- M3 볼트/너트 포켓 또는 인서트 사용

## 12. UI/소프트웨어와 하드웨어 경계

- 기본은 **touch-first**
- 전면 물리 키보드는 제거
- 이름 입력이 필요하면 화면 키보드/임시 서비스 키보드 등 별도 입력 방식을 사용
- 카메라 프리뷰는 현재 브라우저 getUserMedia 구조를 유지할 수 있음
- AI 추론, NFC, 프린터 제어는 백엔드 소유
- 브라우저가 NFC/프린터를 직접 제어하지 않음
- 실제 백엔드 확인 없이 “NFC 등록 성공”, “출력 완료” UI를 표시하지 않음
- 중복 터치/중복 출력 방지 필요
- 전시 중 관람객이 이탈해도 다음 사용자 데이터가 섞이지 않도록 세션 초기화 필요

## 13. 데이터/개인정보 방향

- 원본 얼굴 이미지를 불필요하게 영구 저장하지 않음
- NFC에는 최소 식별/세션 정보만 저장
- 상세 프로필/체험 결과는 로컬 DB/서비스에서 관리
- raw photo를 로그에 남기지 않음
- 카드가 재사용되므로 세션 종료/재발급 시 이전 사용자 연결을 확실히 초기화해야 함

## 17. 현재 제작 판단

프린터 USB 고장은 중요하지만 **프린터 수리를 기다리며 전체 제작을 멈출 필요는 없다.**

현재 가장 안전한 순서는:

디스플레이 프레임 → Pi/화면/카메라 → LED/NFC → 프린터 수리 → 프린터 basket/cradle → 전체 배선 → 통합 테스트.

최종 함체 치수와 프린터 모듈은 실물 피팅 후 잠그며, 초기부터 전체 본체를 한 번에 출력하지 않는다.
