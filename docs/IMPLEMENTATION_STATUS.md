## AI 방식 B 로컬 합성 · 2026-09-22

`POST /api/profile`을 실제 구현하고 운영 UI의 `generateProfile` 경로에
연결했습니다. YuNet의 단일 얼굴 박스와 5개 랜드마크로 얼굴 위치·기울기,
밝기, 선명도를 확인한 뒤 OpenCV GrabCut으로 인물과 배경을 분리합니다.
720×960 중립 배경 위에 촬영 얼굴을 유지해 배치하고, 프로젝트에서 직접
생성한 공용 남색 정장 RGBA 템플릿을 합성합니다. 외부 생성 AI/API 호출은
없으며 실패 시 샘플이나 임의 결과로 전환하지 않습니다.

원본 촬영 이미지는 저장하지 않습니다. 완성 PNG만 메모리에 기본 10분,
최대 8개 유지하고 같은 출처 URL로 전달합니다. 브라우저 초기화 시 DELETE를
요청하며, TTL과 서버 종료 시에도 제거합니다. `operation_id` 재요청은 같은
프로필 ID를 반환합니다.

완료 범위는 **실제 촬영 → 실제 로컬 합성 → SCR-11 결과 미리보기**입니다.
현재 `/api/issue`는 캐릭터 `char_id`만 받으며 NFC/출력 서비스도 미연동이므로,
Mode B 합성 이미지를 실물 사원증에 출력하는 단계는 아직 남아 있습니다.
GrabCut 품질은 배경과 인물의 대비에 영향을 받으므로 전시장에서는 단색 촬영
배경과 Raspberry Pi 실사 표본으로 추가 보정해야 합니다.

## 프론트엔드 1차 구현 · 2026-09-15

## 범위

`sdg331/CarpeDM_EXPO_IDPrinter`의 초기 README 위에 인수인계 문서와 기존 Raspberry Pi 코드/자산을 가져왔습니다. 이 절은 2026-09-15 당시 기록이며, AI B의 최신 상태는 위 2026-09-22 절을 따릅니다.

Figma 파일은 제공되지 않았습니다. `DESIGN.md`의 높은 명암 대비·터치 우선·800×1280 원칙을 적용한 코드 기반 시안입니다. 사용자 피드백에 따라 현재는 화이트·블루 톤으로 구성했으며, 최종 브랜드 컬러 확정은 별도입니다.

## 구현

SCR-01~20과 SCR-90 유휴 경고에 대응하는 화면을 제공합니다. A/B 선택은 촬영 전, 팀은 확정된 6개이며 팀 소개/업무/키워드는 원문을 사용합니다.

- 이름: 앞뒤 공백 제거, 유니코드 코드포인트 1~10자, IME 조합 중 제출 금지.
- 카메라: 실제 스트림·감지 API, 얼굴 없음/다중 인원/권한 오류. 현재 API에 없는 자세 품질·바운딩 박스를 만들어내지 않음.
- AI A: 실제 매칭 API 응답 검증. 원시 점수 미노출, 랜덤 폴백 없음.
- AI B: 화면과 고정 샘플만 제공. 사용자 사진을 외부 서비스로 보내지 않음.
- NFC: 대기/감지/쓰기/검증/실패 화면, 검증 완료와 서버 세션 ID가 있어야 출력 진입.
- 출력: 배지/리포트에 서로 다른 작업 ID. 동작 중 재제출/뒤로 이동 차단.
- 오류: 안전한 재시도 시 입력/결과 유지. 결과 불명 상태는 재출력·홈 복귀·유휴 초기화를 막고 스태프 확인 안내를 유지.
- 초기화: 메모리 상태·사진 Blob 참조·카메라 스트림·작업 ID·리포트 제거. 이전 요청 응답 무효화.
- 운영 UI는 완료 후 15초 초기화와 유휴 45초 경고/60초 초기화를 적용합니다. 진행 중 작업은 유휴 초기화에서 제외하고 25초 작업 타임아웃을 적용합니다. 공개 데모는 발표 중 자동 초기화를 하지 않습니다.
- 폰트: 기존 배지 렌더러에 Windows 맑은 고딕 검색 경로를 추가. 실제 Pi/Mac 경로는 유지.

## 명시적 화면 체험

`?demo=1`에서만 활성화합니다. 카메라·NFC·프린터에 접근하지 않으며 화면 상단과 결과 화면에 예시임을 표시합니다. 이름/팀은 현재 입력값, AI 결과는 고정 샘플입니다. 팀 상세와 AI 방식 상세를 생략해 선택 직후 다음 핵심 단계로 이동하고, 유휴·완료 자동 초기화를 끕니다. 퇴근에서는 이전 관람객 정보를 재사용하지 않고 김미래/디자인팀의 별도 고정 예시를 조회합니다. 날짜·피드백도 예시로 표시합니다.

공개 시연 URL인 `?demo=1`에서는 설정을 숨기고 정상 흐름만 보여줍니다. `?demo=1&controls=1`의 상단 `시연 설정`에서 정상, 지연, 카메라 오류, 얼굴 없음, 다중 인원, AI 오류/시간 초과, NFC 오류/시간 초과, 프린터 오류, 미등록 카드, 기록 없음, 서비스 점검을 선택합니다. 재시도 시나리오는 첫 요청 실패 후 다음 명시적 요청에 성공하도록 고정되어 있습니다.

## 실제 연결할 계약

Mode B는 `frontend/js/api-client.js`에서 같은 출처의 `POST /api/profile`을 직접 호출하고, 홈·세션 초기화 또는 페이지 종료 시 임시 결과 삭제를 요청합니다. 아래의 미연결 장치 메서드는 `frontend/js/live-integrations.js`에 구현해 `liveIntegrations` 객체로 내보냅니다. 기존 REST 경로와 신규 제안 경로를 혼동하지 않도록 미구현 메서드는 명시적으로 중단합니다.

| 메서드 | 성공 시 필수 반환값 |
| --- | --- |
| `registerNfc(profile, context)` | `{ status: 'verified', sessionId: '서버 발급 ID' }` |
| `issueBadge(sessionId, context)` | `{ status: 'success' }` — 실제 완료 확인 후 |
| `resolveCheckout(context)` | `{ sessionId, name, teamId }` |
| `getMirrorTingReport(sessionId, context)` | `{ status: 'available', sessionId, reportId, scenario, summary, ... }` 또는 `{ status: 'not_found' }` |
| `printReport(report, context)` | `{ status: 'success' }` — 실제 완료 확인 후 |

`context`에는 `signal`, `operationId`, `onStatus`가 있습니다. UI 요청 ID는 중복 의도를 식별하는 값이며 사원 번호가 아닙니다. 서버는 같은 `operationId`의 재요청을 중복 실행하지 않고 기존 작업 결과를 반환해야 합니다. 출력 완료/카드 쓰기 결과를 모르면 `UNKNOWN_OUTCOME`으로 중단하고 운영자가 작업을 확인해야 합니다. 현재 레거시 `/api/issue`는 이 보장을 제공하지 않으므로 자동으로 연결하지 않았습니다.

예상되는 오류는 `api-client.js`의 `KioskError(code, retryable)`로 변환합니다. `retryable: true`는 서버 측 중복 방지가 확보되고 재시도가 안전할 때만 사용합니다. 진행 상태는 백엔드가 관측한 경우에만 `onStatus`로 전달하며, 숫자 진행률은 표시하지 않습니다.

## 프론트엔드 최종안 · 2026-09-15

사용자가 제공한 Apple·Toss 디자인 문서를 참고해 홈·AI 카드·처리·완료 화면과 공통 피드백을 마무리했다. 현재 결과와 상세 검증은 `FRONTEND_FINAL.md`가 최신이다. 위 단락들은 구현 이력이다.

- 단정한 사원증 예시, 중립 표면과 명확한 주 행동, 짧고 구체적인 안내를 사용한다. 팀 소개 원문·확정 흐름을 유지한다.
- 화면 이동·뒤로 이동·모달·완료 체크에 짧은 효과를 제공한다. 같은 화면 상태 갱신은 전환을 재시작하지 않으며 모션 감소 설정을 반영한다.
- 카메라 오류에서 복구 방법과 재연결 버튼을 제공한다. 로딩 버튼은 처리 중임을 표시하고 중복 동작을 차단한다.
- 유휴 경고는 계속하기/홈 버튼으로 명시적으로 조작한다. Tab으로 경고가 닫히지 않으며 계속하기 후 이름과 포커스가 유지된다. 유휴 자동 초기화도 확인했다.
- Node 테스트 17개 통과. 800×1280의 입사 A/B·퇴근 전체 흐름과 주요 오류 상태를 재검증했다. 본문·버튼 잘림 없음, 리포트 끝까지 스크롤 확인. 실제 모드의 미연결 안내도 확인했다.
- `docs/design-references/`에 제공 문서와 참고 범위를 보관했다. 폰트·프레임워크·백엔드/API 계약은 변경하지 않았다.
